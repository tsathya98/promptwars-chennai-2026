# PromptWars 2026 — Official Problem Statement & Evaluation Criteria

---

## 🎯 Problem Statement: Recovery and Prevention Platform

> **Design and build a multi-modal, GenAI-powered recovery and prevention platform that supports individuals navigating substance use disorders and their caregivers.**
> 
> The solution must utilize generative AI as a core engine to provide **zero-typing interventions**, **personalized emergency scripts**, backed by **educational resources**, and **contextual safety tools** that empower users and families when cognitive load is highest.

> [!IMPORTANT]
> **Warm-Up & Final Challenge Note:**
> The Problem Statement for both the **Warm-Up Phase** and the **Final Challenge Phase** is **EXACTLY THE SAME**. Building this complete, end-to-end working foundation for the warm-up submission directly serves as the core submission for the final challenge.

> [!TIP]
> **Pro-Tip from Judges & Evaluators:**
> Functional checks are designed to evaluate your application as a whole, not just a single feature. Solutions with thoughtfully connected workflows and meaningful functionality provide evaluators with multiple opportunities to experience your application as intended. A well-rounded application is also more resilient to isolated implementation issues, reducing the likelihood of a single broken flow impacting the overall functional evaluation.

---

## 🛠️ Core Functional Pillars

1. **Zero-Typing Interventions**:
   - High-friction typing fails when cognitive load and stress are highest.
   - Must provide zero-typing options: voice commands, single-tap visual cues, emergency macro buttons, and low-cognitive-load UI.

2. **Personalized Emergency Scripts**:
   - Real-time AI-generated de-escalation, panic response, and craving management scripts customized to the individual's triggers and caregiver context.

3. **Contextual Safety Tools**:
   - Real-time safety status checks, emergency contact triggers, location/situation-aware coping protocols, and risk mitigation tools.

4. **Educational & Caregiver Support**:
   - AI-curated empathetic guidance, actionable resources, and step-by-step crisis playbooks for families supporting loved ones with substance use disorders.

5. **Connected Multi-Modal Workflows**:
   - Seamlessly connects voice, text, and visual inputs/outputs into a cohesive user journey rather than isolated, disconnected widgets.

## 📊 Evaluation Framework & Parameter Impact Breakdown

Your final score is the sum of all 6 parameters (evaluated automatically on the platform):

| Parameter | Impact Level | Description & Focus Area |
| :--- | :---: | :--- |
| **Code Quality** | 🔴 **High Impact** | Clean, readable, well-structured, modular architecture. |
| **Problem Statement Alignment** | 🔴 **High Impact** | Directly targets substance use recovery, caregiver support, zero-typing, and emergency interventions. |
| **Security** | 🟡 **Medium Impact** | Safe practices, no exposed secrets, safe handling of sensitive recovery data. |
| **Efficiency** | 🟡 **Medium Impact** | Optimal memory & response time, low latency AI streaming. |
| **Testing** | 🟢 **Low Impact** | Unit/integration tests, easily testable and maintainable code structure. |
| **Accessibility** | 🟢 **Low Impact** | Keyboard nav, accessible color contrast, screen-reader friendly under high cognitive stress. |

> [!IMPORTANT]
> - **High Impact Parameters (Code Quality & Alignment)** carry the heaviest weight — prioritize these to move up the leaderboard.
> - **Medium Impact (Security & Efficiency)** prevent point losses.
> - **Low Impact (Testing & Accessibility)** act as tie-breakers between top ranks.
> - Only the **final submission score** counts. Best attempt scores are not used. Warm-up scores do not count.

## ⚠️ Disqualification Rules (Zero Tolerance)

After the challenge closes, evaluators run hands-on functional testing. Projects with any of the following will be **disqualified**:

| ❌ Will Get Disqualified | ✅ Do This Instead |
| :--- | :--- |
| **Static / Hardcoded pages** (UI shows an outcome, but no real logic/model produces it) | **Every feature must run end-to-end**. If it's in your project, it needs to work. |
| **Mock or fake data** (sample/placeholder data presented as real output) | **Wire up actual, working API / model calls** — no canned responses. |
| **Hallucinated AI responses** (outputs not generated by a working AI call) | Genuine real-time model generation. |
| **False positives** (feature appears to work in demo but fails testing) | **Test end-to-end before submitting**. Walk through your project as an evaluator would. |
| **Missing Auth Credentials** | **Share test credentials** in submission notes if login/auth is used. |
